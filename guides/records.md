# Records and feedback

Load before changing shared status, issue records, evidence, instructions or release claims. Before a completion or release claim, run the project's release-mode record checks and inspect the specification evidence.

The orchestrator owns consolidated records; leads own issue details and evidence. The orchestrator writes shared-record updates or assigns one existing lead as the writer; record batches are not subagent tasks. Reread before editing. Resume from the short current-status page, then the relevant lead-owned issue record. Keep earlier checkpoints, decisions and failed attempts in dated history, and replace current status instead of appending progress. Preserve incoming section links when compacting.

Keep requirements, decisions, designs, status, feedback and dated proof in the places the project's setup records. Update the owning record first; create or link files only for distinct reusable work. Before a rewrite, preserve the superseded text in dated history with an index entry, and never edit historical snapshots. Preserve large raw logs once. Reference unchanged qualified inputs instead of recopying them into each successor. A hash or archive check does not qualify behaviour.

Record user defects, corrections and requests before closing, unless the user says otherwise or recording makes no sense. Find a matching report and reopen regressions. For a new report, allocate the next unused ID from the freshly reread list of reports and keep its columns, status meanings, original wording, acceptance requirements and evidence links. Date reports and keep screenshots. Record agent discoveries under the matching report, labelled with their source; if none applies, use the relevant design, evidence and status records. Move detail to a resolved area only when every covered issue is closed or superseded.

Record substantial checks with the build or local changes, commands and results, proof and remaining gates. Separate source, synthetic, native, platform, live-provider and human evidence, and never claim a check passed that was not run. Update issue, evidence and shared status through their assigned writers before delivery. A helper or bundle alone does not finish an issue.

Close only after all current-artifact checks and required human acceptance, with evidence. Supersession needs an explicit linked decision. Recording is not implementation authority.

Run the project's matching record checker whenever its record changes. Report later-version failures separately and never relabel them to force a pass. Documentation checks do not certify runtime or deployment.

Keep user reports short: pending decisions or reviews first, then changes, results, limits and the next action. Revise instructions when workflows change or a need is demonstrated. Keep tool schemas, copied system prompts and generic motivational rules out of instructions; put specialist procedures in scoped guides and temporary constraints in the task.
